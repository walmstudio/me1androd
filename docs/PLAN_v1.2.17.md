# План и проверка v1.2.17

## Статус

GEARMASS и весь план **не завершены**. Четвёртый шаг этапа 8: исследование. Код runtime, генератора и `rt.h` не менялся, поэтому ни перегенерация, ни пересборка не требуются; добавлен только тест. APK и полная игра не собирались; ARM, телефон и поведение под нагрузкой не проверены. Улучшение FPS не обещается. Для отката сохраните работающую v1.2.3.

## Что сделано

Добавлен `tests/recomp/audit_x87_inline_native.py`: он вызывает `fpsse.x87` для безоперандных инструкций (то есть проверяет именно то, что окажется в сгенерированном C), собирает стенд и сравнивает с аппаратным x87 значения (допуск 2e-15 относительный; у тригонометрии ещё 5e-20·(|x|+1) абсолютный из-за 66-битного π в x87, у FPTAN дополнительно ×(1+tan²)), TOP и статусные биты. Исходные данные: 36 специальных значений (±0, субнормальные, максимальные, ±inf, ±NaN, π, 2^63 и т. п.) и 4 000 случайных; для двухоперандных инструкций пары.

### Результаты (x86-64, gcc 13.3, seed 11, исключения маскированы)

Обычный генератор:
- Значения и TOP совпадают для FSQRT, FCHS, FABS, FRNDINT, FXTRACT, FSCALE, F2XM1 (|x| ≤ 1), FPATAN, FYL2X, FPREM, FPREM1 (без частичной редукции), FSIN, FCOS, FSINCOS (при |x| < 2^63).
- Расхождения значений: **FPTAN при ±inf/NaN** (runtime кладёт 1.0, x87 кладёт NaN; 4 случая). При |x| ≥ 2^63 (известное, исправляется `--trig-fix`) расходятся FSIN/FCOS/FSINCOS/FPTAN (660–710 случаев на инструкцию, не считаются ошибкой теста).
- FYL2XP1 расходится только при субнормальном x и огромном y (6 случаев): промежуточное `log1p(x)/ln2` в double теряет точность; пропускается как документированное ограничение.

`--trig-fix` (экспериментальный генератор): расхождений значений и TOP у FSIN, FCOS, FSINCOS, FPTAN **0**, включая |x| ≥ 2^63, ±inf и NaN.

Статусные биты: PE/IE/C1 не совпадают после FSQRT, FPATAN, FYL2X, F2XM1 и тригонометрии (встроенные выражения их не ставят). Для кода, который читает только C0–C3 после сравнений и FPREM/FXAM, это не влияет; для кода, читающего PE/IE, влияет.

Вывод: что-либо менять в стандартном генераторе по этому аудиту не требуется для значений; единственное практическое расхождение (FPTAN при ±inf/NaN и |x| ≥ 2^63) уже закрыто экспериментальным генератором, который по-прежнему выключен по умолчанию и требует долгой регенерации.

### Запуск

```sh
python3 tests/recomp/audit_x87_inline_native.py              # обычный генератор, код 1 из-за FPTAN(±inf/NaN)
python3 tests/recomp/audit_x87_inline_native.py --trig-fix   # код 0
python3 tests/recomp/audit_x87_inline_native.py -v           # примеры расхождений статуса
```

Тест намеренно не маскирует найденные расхождения. Ранее проверенные нативные тесты (FRNDINT, FIST, FSCALE, FPREM, FPREM special, FPU misc) на этой версии не перезапускались: runtime идентичен v1.2.16. Python-тесты с capstone/keystone/unicorn, GEARMASS, Vulkan и Android Java не запускались.

## Осталось

- Этап 8: 80-битная арифметика и полная эмуляция исключений x87 не реализованы; PE/IE/C1 в арифметике и встроенных инструкциях не моделируются; DE не моделируется; расхождения тригонометрии около кратных π ограничены абсолютной ошибкой порядка 1e-20·|x| (аппаратная редукция с 66-битным π). Решение, когда включать `--trig-fix` по умолчанию, не принято (нужны ARM и реальная игра). Локальные регистры, TSO, Android PGO и нативные замены требуют проверки и измерений; внедрение в генерацию требует долгой сборки.
- Vulkan: настоящая упреждающая компиляция будущих pipeline не реализована; secondary buffers и восстановление остаются экспериментальными и не проверены на Mali.
- Длительная проверка GEARMASS AUTO, датчиков, авторазрешения, FPS, нагрева, батареи и стабильности на телефоне; оценить пользу распараллеливания mip-карт и конвертации данных.
