# План и проверка v1.2.3

## Реализовано

- **Авторазрешение между сеансами**, отдельно включается в GEARMASS, по умолчанию выключено. Работает только в AUTO с лимитом FPS. Используются не менее 180 секунд активной сцены (от 60 draw/кадр, без загрузок и видео), реальные размеры backbuffer и только подходящие показатели текущего лимита. GPU-bound при средней частоте ниже 85% лимита: снижение каждой стороны на 1/8, не ниже 640×360. Для повышения — два подходящих учтённых сеанса подряд (не менее 80% времени у лимита, FPS не ниже 97%, без высокого нагрева). Верхний предел — выбранное вручную разрешение. Повторная обработка той же записи запрещена; обновление не применяется внутри игры. Значение сохраняется на диске, при выключении само не восстанавливается. Без фактического совпадения разрешения, надёжных данных GPU или достаточной сцены система может не менять размер. Сеанс v1.2.2 не содержит новых полей — сначала сыграйте на v1.2.3.
- **Экспериментальное фоновое создание Vulkan pipeline** (`ME1_VK_ASYNC_PIPE=1`, по умолчанию выкл.). Pipeline создаётся параллельно с подготовкой констант того же вызова, затем обязательно ожидание; рисование не пропускается только из-за ожидания. Перекрываемого времени может быть мало, поэтому эффект и устранение рывков не гарантируются. `ME1_VK_PIPEIDLE=1` сохраняет последовательное создание и обходной путь для Mali. Это не предсоздание pipeline и не этап secondary command buffers.

## Проверено локально

- Тест GEARMASS: 234 успешно / 0 ошибок; авторазрешение: 20 / 0, включая один результат на сеанс, ручной потолок, два сеанса для повышения и отключение для тестового запуска. Проверены сохранение фактического размера, запрет при разных backbuffer и защита статистики от теста без окна.
- Vulkan/lavapipe: test_gl 641 / 0 при выключенном и включённом фоне, а также при включённом PIPEIDLE. test_cmd 430 / 0 в обоих режимах, CRC итогового кадра `cc79f631` в обоих. Установленный Vulkan Validation: 0 сообщений в обоих режимах. Это синтетические тесты программного Vulkan, не доказательство стабильности драйвера телефона.
- Java: `javac` успешно; полная сборка APK и игра на телефоне не выполнялись.
- Дифференциальный тест перекомпилятора, 200 случаев на категорию, seed 11: x87, SSE, MMX, int и lock — по 200 / 0; x87t — 184 / 16. Точно такие же 16 расхождений наблюдаются на v1.2.2 при тех же зависимостях, то есть они не появились в v1.2.3. Не установлено, какие случаи вызваны приближениями реализации, а какие особенностями эталона Unicorn; игнорировать их нельзя.

## Ещё не готово

- **Вторичные Vulkan command buffers (этап 2).** Нужны разбиение при смене целей/очистках/копировании/present, независимые snapshot состояния, пулы, дескрипторы и области памяти на поток, сохранение порядка и корректные occlusion queries, а также сравнение кадров и проверка ошибок/сброса устройства. В данной версии это не реализовано. Замеры пользователя для Mali-G52 указывали около 90–100 мс GPU/кадр и около 25 мс CPU-записи на 2000 draw, поэтому ускорение записи может не решить главный bottleneck.
- **Оптимизация перекомпилятора (этап 8)**: локальные регистры, более глубокий анализ TSO, PGO и нативные замены горячих функций не реализованы как завершённый этап. Перед изменением семантики нужны исправление/разбор x87t, тесты исключений и потоков, дифференциальная проверка и полная регенерация/долгая пересборка игры пользователем.
- **На устройстве**: проверить длительную игру, переключения, нагрев и AUTO, качество/разрешение, Vulkan с обычным драйвером и с `ME1_VK_ASYNC_PIPE=1`; сравнить логи, частоту и изображение. Экспериментальные функции не считать проверенными для Mali до этих испытаний.
