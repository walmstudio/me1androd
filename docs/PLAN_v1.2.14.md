# План и проверка v1.2.14

## Статус

GEARMASS и весь план **не завершены**. Это первый шаг этапа 8: исправлена одна воспроизведённая проблема runtime x87. APK и полная игра не собирались; реальный ARM, телефон и поведение под нагрузкой не проверены. Улучшение FPS не обещается. Для отката сохраните работающую v1.2.3.

## Что изменено

`rt_round_fcw` (`runtime/rt_fp.c`) для режимов округления гостя «вниз» и «вверх» вызывал `floor()` и `ceil()` из libm. При режиме округления хоста FE_DOWNWARD glibc возвращает `-0` для `floor(+0.1)`, `floor(+0)` и т. п., поэтому FRNDINT мог выдать неверный знак нуля, вопреки комментарию о независимости от fenv. Теперь используется `trunc` с точной поправкой ±1 на целом значении меньше 2^53; NaN и бесконечности проходят без изменений. Исправление затрагивает FRNDINT и (без видимого эффекта для целых результатов) FISTP.

Изменён только `runtime/rt_fp.c`, не `rt.h`, не генератор и не `out/`: перегенерация и полная перекомпиляция игровых C-файлов не требуются, нужна пересборка runtime.

## Проверки

Аппаратный x86-64, gcc 13.3, исключения маскированы:
- FRNDINT (`tests/recomp/test_frnd_native.c`): до исправления **5 ошибок из 65 938** при `-O1`…`-O3` (при `-O0` ошибок не было; заявленное в v1.2.12 «65 938/0» зависит от сборки и libm), после исправления **65 938/0** при `-O1`, `-O2`, `-O3` и под UBSan (`-O1`).
- FISTP/FISTTP **100 512/0**, FSCALE **10 289/0**, FPREM **40 022/0** при `-O1`…`-O3` без изменений.
- Тесты на Python (capstone, keystone, unicorn), GEARMASS, Vulkan и Android Java в этой версии не запускались: изменение их не затрагивает, но повторная проверка не выполнялась.

```sh
gcc -O2 -fwrapv -fno-strict-aliasing -ffunction-sections -Wl,--gc-sections -Iruntime tests/recomp/test_frnd_native.c runtime/rt_fp.c -lm -o /tmp/test_frnd && /tmp/test_frnd
```

## Осталось

- Этап 8: 80-битная арифметика и полная эмуляция исключений x87 не реализованы. Расхождения вокруг кратных π (аудит `--trig-fix`), статусные биты FPREM при недопустимых операндах, экспериментальная тригонометрия, локальные регистры, TSO, Android PGO и нативные замены требуют проверки и измерений; внедрение в генерацию требует долгой сборки.
- Vulkan: настоящая упреждающая компиляция будущих pipeline не реализована; secondary buffers и восстановление остаются экспериментальными и не проверены на Mali.
- Длительная проверка GEARMASS AUTO, датчиков, авторазрешения, FPS, нагрева, батареи и стабильности на телефоне; оценить пользу распараллеливания mip-карт и конвертации данных.
