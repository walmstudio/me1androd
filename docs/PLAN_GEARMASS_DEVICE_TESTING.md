## Цель

Проверить работу системы GEARMASS (распределение нагрузки) на реальных устройствах:
- Корректность работы режимов (ECO, BALANCE, PERF, MAX, AUTO)
- Поведение тепловых датчиков (Android Thermal API, Linux sysfs)
- Авторазрешение экрана между сеансами
- Стабильность при длительной игре
- Влияние на FPS, нагрев и расход батареи

---

## Тестовые устройства

### Минимальный набор

1. **Android (ARM64)**: телефон/планшет с Android 10+
   - Mali GPU (например, Helio G85 / Mali-G52)
   - Snapdragon (например, Snapdragon 8 Gen 1 / Adreno 730)
   
2. **Linux (x86-64)**: ПК с видеокартой
   - Mesa/Intel или AMD/NVIDIA
   
3. **Linux (aarch64)**: опционально, если доступен
   - Raspberry Pi 5, Asahi Linux на Apple Silicon и т.п.

### Рекомендуемые конфигурации

- **Слабое устройство** (4 ядра, Mali-G52): проверка режима ECO
- **Среднее устройство** (6-8 ядер, Adreno 6xx): проверка AUTO и BALANCE
- **Мощное устройство** (8+ ядер, флагманский GPU): проверка MAX и PERF

## 1. Подготовка к тестированию

### 1.1 Сборка APK для Android

```bash
# Убедиться, что out/ содержит перекомпилированные модули игры
ls -la out/exe out/msvcr80 out/msvcp80 out/d3dx9 out/physxcore out/ogg out/vorbis out/bink

# Сборка нативных библиотек
make -j$(nproc) game-lib                    # libme1game.so, libme1run.so
make build/android/libme1spv.so             # SPIR-V компилятор для Vulkan

# Сборка APK
make apk
# → android/out/me1port-launcher.apk
```

### 1.2 Сборка для Linux

```bash
# Проверка зависимостей
sudo apt-get install libsdl2-dev  # или аналог для вашего дистрибутива

# Сборка
make -j$(nproc) linux
# → build/linux/me1-linux, me1-launcher, me1cfg, libme1spv.so

# Опционально: установка в ~/.local
linux/install.sh
```

### 1.3 Подготовка файлов игры

Убедиться, что копия Mass Effect (2007) доступна:
- **Android**: `/sdcard/MassEffect/` (или `/sdcard/Mass Effect/`)
- **Linux**: любая папка, указанная в лаунчере

## 2. Функциональное тестирование

### 2.1 Режимы нагрузки (все платформы)

#### Тест ECO
```
Цель: минимальное энергопотребление
Настройки: Нагрузка → ECO
Ожидание:
  - FPS limit 30
  - 0 рабочих потоков
  - ME1_D3D_CMD=0 (прямые вызовы)
  - Низкая загрузка CPU

Проверка:
  1. Запустить игру
  2. Открыть меню → проверить ~30 FPS
  3. Зайти в игру → проверить стабильный 30 FPS
  4. Проверить лог: [gearmass] ECO: workers 0/0, cmd 0
```

#### Тест BALANCE
```
Цель: баланс производительности и энергопотребления
Настройки: Нагрузка → BALANCE
Ожидание:
  - Нет лимита FPS
  - До 2 рабочих потоков
  - ME1_D3D_CMD=2 на 4+ ядрах
  - Умеренная загрузка

Проверка:
  1. Запустить игру
  2. Меню → проверить 60 FPS
  3. Игра → проверить стабильность
  4. Лог: [gearmass] BALANCE: workers 2/2, cmd 2 (на 4+ ядрах)
```

#### Тест PERF
```
Цель: высокая производительность
Настройки: Нагрузка → PERF
Ожидание:
  - Все свободные рабочие потоки
  - Закрепление на быстрых ядрах (prime=1)
  - ADPF target 8ms, uclamp 512
  - Анизотропия повышается автоматически

Проверка:
  1. Запустить игру
  2. Зайти в локацию с текстурами
  3. Проверить HUD: "AF4" → "AF8" → "AF16" (при свободном GPU)
  4. Лог: [gearmass] PERF: workers N/N, prime cores, AF повышается
```

#### Тест MAX
```
Цель: максимальная производительность
Настройки: Нагрузка → MAX
Ожидание:
  - Все рабочие потоки
  - 2 кадра вперёд (ahead=2)
  - Активное ожидание (spin=2)
  - uclamp 1024

Проверка:
  1. Запустить игру
  2. Боевая сцена с множеством врагов
  3. Проверить максимальный FPS
  4. Лог: [gearmass] MAX: ahead 2, workers N/N, spin 2
```

#### Тест AUTO
```
Цель: автоматический выбор режима по замерам
Настройки: Нагрузка → AUTO (по умолчанию)
Ожидание:
  - Автоматическое переключение BALANCE ↔ PERF ↔ MAX
  - Реакция на нагрев
  - Адаптация к типу сцены (меню, загрузка, игра)

Проверка:
  1. Включить HUD: ME1_GM_HUD=1 или через лаунчер
  2. Запустить игру
  3. Меню → ожидание BALANCE
  4. Загрузка → ожидание MAX
  5. Игра (30 FPS cap) → ожидание step down к BALANCE через ~6-8 сек
  6. Игра (упор в CPU) → ожидание MAX
  7. Игра (упор в GPU) → ожидание PERF с ahead=2
  8. Проверить лог каждые 5 секунд
```

### 2.2 Тепловые датчики

#### Android
```
Настройки: AUTO, играть 15-30 минут

Проверка:
  1. HUD показывает "heat XX%"
  2. При нагреве (heat ≥90%) → step down к BALANCE/ECO
  3. После охлаждения (30 секунд прохлады) → step up обратно
  4. Лог: thermal headroom readings, thermal step-down events
  5. Файл статистики: Documents/me1_gearmass_last.txt
     - active_seconds > 0
     - heat_max < 100
     - thermal_partial_seconds (если датчики пропадали)
```

#### Linux
```
Настройки: AUTO

Проверка (AMD/Intel CPU):
  1. cat /sys/class/thermal/thermal_zone*/type
     → должен найти CPU/SoC зоны
  2. Запустить игру с HUD
  3. Наблюдать "heat XX%" в HUD
  4. Нагрузить систему → проверить step down при нагреве
  5. Лог: [gearmass] thermal: N sensors (coretemp/k10temp/zenpower)

Проверка (если датчики не найдены):
  1. HUD: "heat ?" (неизвестно)
  2. AUTO работает без тепловых данных
  3. Лог: [gearmass] thermal: no sensors
```

### 2.3 Авторазрешение экрана (Android)

```
Настройки:
  - Разрешение: 1280x720
  - FPS limit: 30
  - Включить "Авторазрешение" в лаунчере
  - Режим: AUTO

Проверка понижения:
  1. Играть 3-5 минут (сцена с упором в GPU)
  2. Выйти из игры
  3. Открыть лаунчер → разрешение должно стать 1120x630
  4. Файл: Documents/me1_gearmass_last.txt
     - active_gpu > 50% времени
     - active_capped < 10%

Проверка повышения:
  1. Играть 3-5 минут (стабильный 30 FPS, GPU не загружен)
  2. Выйти и перезапустить → ещё 3-5 минут
  3. После двух сеансов разрешение должно вернуться к 1280x720
  4. Условия:
     - active_heat_known ≥ 95% (полные данные о температуре)
     - heat_max < 80 (прохладно)
```

### 2.4 Буфер команд (ME1_D3D_CMD)

```
Тест режима 0 (прямые вызовы):
  ME1_D3D_CMD=0 → игра должна работать как раньше

Тест режима 1 (буфер, тот же поток):
  ME1_D3D_CMD=1 → проверка записи/воспроизведения
  - Никакого выигрыша в производительности
  - Картинка идентична режиму 0

Тест режима 2 (отдельный поток рендера):
  ME1_D3D_CMD=2 → параллельная отрисовка
  - На 4+ ядрах должен быть выигрыш
  - Лог: "cmd X KB/frame, game waits Y ms/frame"
  - Картинка идентична режимам 0 и 1
```

### 2.5 Распараллеливание

#### DXT/ATI распаковка
```
Настройки:
  - ME1_TEX_BC=0 (принудительная распаковка на CPU)
  - ME1_GM_WORKERS=4
  - Высокое разрешение текстур в игре

Проверка:
  1. Загрузить сцену с множеством текстур
  2. Лог должен показать использование worker threads
  3. FPS не должен сильно падать при загрузке текстур
```

#### SPIR-V компиляция (Vulkan)
```
Настройки:
  - Драйвер: Vulkan
  - ME1_VK_SPV_MT=1 (по умолчанию)

Проверка:
  1. Первый запуск игры (пустой кэш шейдеров)
  2. Лог: параллельная компиляция VS+PS
  3. Время первого кадра должно быть меньше, чем с ME1_VK_SPV_MT=0
```

## 3. Тестирование стабильности

### 3.1 Краткий тест (30 минут)

```
Конфигурация: AUTO, все настройки по умолчанию

Сценарий:
  1. Новая игра или загрузка сохранения
  2. Меню → выбор персонажа/задания
  3. Переход в игровую локацию
  4. 10 минут геймплея (бой, диалоги, перемещение)
  5. Переход в другую локацию
  6. Ещё 10 минут геймплея
  7. Сохранение и выход

Проверка:
  - Нет вылетов/зависаний
  - FPS стабилен
  - Нет графических артефактов
  - Лог без FATAL/ERROR
  - Файл статистики корректно записан
```

### 3.2 Длительный тест (2+ часа)

```
Конфигурация: AUTO

Сценарий:
  1. Прохождение 2-3 миссий подряд
  2. Множественные переходы между локациями
  3. Разные типы сцен: бои, диалоги, катсцены, инвентарь
  4. Мониторинг температуры устройства

Проверка:
  - Общая стабильность
  - Нет накопления утечек памяти
  - AUTO корректно реагирует на изменение нагрузки
  - Thermal throttling срабатывает при необходимости
  - Батарея не перегревается (Android)
```

### 3.3 Стресс-тест (переключение режимов)

```
Сценарий:
  1. Запустить игру в ECO
  2. Через 5 минут переключить на BALANCE (выход → лаунчер → режим → запуск)
  3. Через 5 минут → PERF
  4. Через 5 минут → MAX
  5. Через 5 минут → AUTO
  6. Повторить цикл 2-3 раза

Проверка:
  - Плавное переключение без вылетов
  - Настройки применяются корректно
  - Лог показывает смену режима
```

## 4. Тестирование производительности

### 4.1 Замеры FPS

Использовать встроенный счётчик (`ME1_SHOW_FPS=1` или через лаунчер)

#### Сравнение режимов
```
Локация: одна и та же сцена (например, Цитадель)
Сохранение в фиксированной точке

Тест:
  1. Загрузить сохранение → ECO → играть 2 минуты → записать средний FPS
  2. Перезагрузить → BALANCE → 2 минуты → FPS
  3. Перезагрузить → PERF → 2 минуты → FPS
  4. Перезагрузить → MAX → 2 минуты → FPS

Ожидаемый результат:
  ECO: ~30 FPS (limit)
  BALANCE: 35-50 FPS (зависит от устройства)
  PERF: 40-60 FPS
  MAX: 45-70 FPS
```

#### Сравнение ME1_D3D_CMD
```
На 4+ ядрах:

  ME1_D3D_CMD=0 → baseline FPS
  ME1_D3D_CMD=2 → должен быть выигрыш 5-15% (если упор в CPU)

На 2-3 ядрах:
  ME1_D3D_CMD=0 ≈ ME1_D3D_CMD=2 (недостаточно ядер)
```

### 4.2 Температура и энергопотребление (Android)

```
Инструменты:
  - Termux + sensors (если доступно)
  - AccuBattery или аналог
  - Встроенная статистика Android

Тест:
  1. Зарядить устройство до 100%
  2. Отключить от зарядки
  3. Играть 1 час в режиме AUTO
  4. Записать:
     - Начальную и конечную температуру
     - Расход батареи (%)
     - Средний FPS
  5. Повторить для ECO и MAX

Ожидаемый результат:
  ECO: самый низкий нагрев и расход батареи
  AUTO: средний (адаптируется)
  MAX: самый высокий нагрев и расход
```

### 4.3 Влияние анизотропии (PERF/MAX)

```
Настройка: PERF или MAX с ME1_GM_QUALITY=1

Тест:
  1. Локация с множеством текстур (например, Новерия)
  2. Включить HUD
  3. Наблюдать изменение "AF1" → "AF2" → "AF4" → "AF8" → "AF16"
  4. Визуально оценить качество текстур на расстоянии
  5. Проверить изменение FPS (должно упасть на 5-10% при AF16)

Ожидание:
  - Качество улучшается постепенно
  - При загрузке GPU > 90% анизотропия снижается обратно
```

### 5.1 Лог последнего запуска

**Android**: `/sdcard/Documents/me1exe_run.log`
**Linux**: `~/.local/share/me1port/me1exe_run.log`

Проверить наличие:
```
[gearmass] CUSTOM, 8 cores (symmetric), worker pool up to 5, thermal: 2 sensors...
[gearmass] AUTO:MAX: cpu-bound main | 58.1 fps, 1200 draws/frame | CPU 2.3/8 cores...
[gearmass] thermal step down: headroom 0.92 >= 0.90, PERF -> BALANCE
```

Проверить отсутствие:
```

ERROR (кроме известных предупреждений)

```

**Android**: `/sdcard/Documents/me1_gearmass_last.txt`

```
run_id=<UUID>
mode=AUTO
resolution=1280x720
active_seconds=245
active_fps=7350.5
fps_limit=30
active_gpu=147
active_capped=220
heat_max=85
fps_limit_mixed=0
active_heat_known=245.0
thermal_partial_seconds=0
```

### 5.3 Индикатор HUD

Включить: `ME1_GM_HUD=1` или через лаунчер

Формат:
```

```

Проверить:
- Режим (AUTO:MAX, BALANCE, и т.д.)
- Классификация (cpu-bound, gpu-bound, capped, loading, idle, video, wait-bound)
- Загрузка CPU (X/N cores)
- Загрузка GPU (%)
- Нагрев (% headroom или "?" если неизвестно)
- Анизотропия (AFN)

## 7. Известные ограничения и что проверять особенно

### Критические области

1. **Тепловые датчики (Linux)**:
   - Частичная потеря датчиков (thermal_partial_seconds)
   - Некорректные показания (вне диапазона)
   - Отсутствие датчиков на некоторых системах

2. **Авторазрешение**:
   - Смешанные FPS limits (fps_limit_mixed=1) должны игнорироваться
   - Недостаточное покрытие температурных данных (active_heat_known < 95%)
   - Режим не AUTO должен пропускать адаптацию

3. **Буфер команд (ME1_D3D_CMD=2)**:
   - Copy-on-write динамических буферов
   - Синхронизация Lock/Unlock
   - Удаление объектов в правильном порядке
   - Occlusion queries (результаты доступны после рендера)

4. **Параллелизм**:
   - Race conditions в worker pool
   - Распаковка DXT даёт одинаковый результат независимо от числа потоков
   - SPIR-V компиляция не ломает шейдеры
